# Dataset Description

## Source and Collection

The dataset consists of real hotel search and booking logs from Expedia, originally released as part of the 2013 ICDM/Expedia Personalized Hotel Search competition on Kaggle. The data was collected through server-side event logging on Expedia's production platform: each time a user submitted a hotel search, the system recorded every property displayed to that user along with any subsequent clicks or bookings. Because the records originate directly from Expedia's live platform rather than from surveys or synthetic generation, each value corresponds to a real user action. The data spans eight months of activity from November 1, 2012 through June 30, 2013, covering 34 country-specific Expedia sites (e.g., Expedia.com, Expedia.co.uk) and 136,886 unique hotel properties worldwide.

## Structure and Key Columns

The dataset contains **9,917,530 rows and 54 columns**. Each row represents a single hotel impression — one property shown to one user in one search session. Search sessions are identified by `srch_id`, which groups all hotels a user saw in a single query; there are 399,344 unique sessions, with a median of 25 hotels shown per search. The combination of `srch_id` and `prop_id` (unique hotel identifier) uniquely indexes each row.

The 54 columns fall into six groups. **Outcome variables**: `booking_bool` (1 if the user booked this hotel; 2.79% positive rate) and `click_bool` (1 if clicked; 4.47% positive rate). **Position and randomization**: `position` gives the hotel's display rank (1 = top); `random_bool` flags the 29.6% of sessions where Expedia randomly shuffled the result order rather than applying its algorithm — a natural experiment built into the data. **Hotel quality**: `prop_starrating` (0–5 stars), `prop_review_score` (0–5 aggregate user rating), `prop_brand_bool` (major brand flag), and `prop_location_score1` (Expedia's proprietary location attractiveness score). **Pricing**: `price_usd` (displayed price; median \$122, highly right-skewed) and `prop_log_historical_price` (log of the hotel's long-run average price). **Competitor pricing**: eight sets of `comp{N}_rate` / `comp{N}_inv` / `comp{N}_rate_percent_diff` columns recording whether Expedia's price is cheaper, equal, or more expensive than each of eight competitor platforms (55–98% null, reflecting incomplete price scraping). **Search context**: `srch_booking_window` (days until check-in), `srch_length_of_stay`, `srch_adults_count`, `srch_room_count`, and `srch_saturday_night_bool`.

## Limitations and Biases

Three issues are central to interpreting this dataset correctly. First, **position bias**: hotels at rank 1 book at a rate of 14.1% versus 1.6% at rank 15, because Expedia's algorithm places properties it expects to convert at the top. Display position is therefore a confounder in any analysis of what drives bookings, and must be controlled for either by including `position` as a covariate or by restricting analysis to the `random_bool=1` sessions where order was randomized. Second, **class imbalance**: `booking_bool` is positive in only 2.79% of rows, making accuracy a misleading evaluation metric — AUC-ROC is used instead, with models trained using balanced class weights. Third, **user history missingness**: `visitor_hist_starrating` and `visitor_hist_adr_usd` are approximately 94% null, not randomly, but because most users in the dataset have no prior Expedia booking history; imputing these with the observed mean would misrepresent first-time visitors. Additionally, competitor pricing columns are largely absent (55–98% null), reflecting the practical difficulty of real-time price scraping, so a null does not indicate the competitor lacked a price. Finally, the data covers a single eight-month window on one platform, which limits generalizability to other booking sites or time periods.
